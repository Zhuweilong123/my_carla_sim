# 参数一致性检查（2026-10-01）

检查范围为轻量级仿真的物理引擎、局部 DP+QP/baseline、巡航 LQR/MPC/PID、泊车 ROS 适配、场景切换与配置文件。物理参数由仿真器定义，通过同一运行的 `sim/context` 分发；算法权重、采样间距和安全余量由各模块管理。

## 已修复的问题

| 参数 | 原行为及影响 | 当前行为 |
| --- | --- | --- |
| 动力学最大积分子步 | LQR 遗漏时间子步上限，50 ms 周期下与车辆的 20 次积分不一致，导致跟踪偏差及反复停车 | LQR/MPC 从上下文同步 `dynamic_max_substep_s`，与物理端相同 |
| 物理步长 | 基础 `SimulationEngine` 固定 0.05 s，只有倒车适配器使用配置 | 基础引擎读取、校验 `config.physics_dt`；默认 `step()` 和 reset 均使用该值；评估入口也写入其 `dt` |
| 局部规划车身几何 | 固定 4 m × 2 m，修改仿真车辆尺寸后规划的碰撞范围仍不变 | DP+QP/baseline 每个 run 从 `vehicle_parameters` 读取车长、车宽；默认车长统一为 `a+b+body_overhang=3.91 m` |
| 泊车几何与转角 | 仅同步目标速度，默认车长 4.9 m、轴距 2.91 m、转角 0.5 rad，与自定义车辆不一致 | ROS 适配同步车长、车宽、轴距、最大转角；规划和控制使用同一份 `ParkingConfig` |
| 算法选择与模型输入 | 拼错控制器名称会静默使用 LQR；显式车辆元组可与 `vehicle_params` 冲突 | 拒绝未知控制器和冲突参数；同时提供车辆元组与物理参数时必须一致 |
| 非法控制参数 | 部分 LQR/PID 参数允许 NaN、无穷大或非法周期进入计算 | 在构造阶段校验周期、物理模型、Q/R、PID 权重、jerk 和反馈预览时间 |
| 运行中修改物理步长 | ROS 参数值可变化，物理定时器与执行器仍用旧周期 | 拒绝 `physics_dt` 热修改并说明需重启，防止显示值与执行对象失配 |
| 未使用的配置 | simulator 的 `speed_profile_lookahead_m` 没有声明/消费 | 删除该无效项，保留控制节点实际使用的前瞻距离 |

## 参数来源与更新规则

| 参数组 | 单位和来源 | 消费者 / 生效时机 |
| --- | --- | --- |
| a、b、质量、侧偏刚度、惯量 | m、kg、N/rad（负号约定）、kg·m²；仿真器 `VehicleParams` | 物理引擎和巡航模型；当前 run 的上下文激活时同步 |
| 车身几何 | 车长为轴距加总悬长，宽度单位 m | 物理碰撞、局部规划、泊车碰撞；新 run 重新读取 |
| 最大前轮角 | rad，物理转角而非归一化输入 | 执行器、LQR/MPC、泊车；新 run 同步 |
| 最大加速/减速 | m/s²，幅值为正 | 物理油门/制动映射及巡航 PID 限幅；新 run 同步 |
| 执行器延迟、惯性、角速度 | s、s、rad/s；假设参数 | 仿真执行器及巡航增广模型；延迟必须为物理周期整数倍；场景上下文同步参数，状态反馈实际 FIFO |
| 目标速度 | 上下文及路线限速为 km/h；模型速度为 m/s | 巡航/PID 与泊车入口分别换算一次；路线限速乘目标比例，弯道再受横向加速度约束 |
| 物理周期与积分子步 | s；`physics_dt` 和 `dynamic_max_substep_s` | 前者决定控制预测周期，后者决定周期内积分；控制节点状态回调触发，同一时间戳只处理一次 |
| 道路范围 | 地图/场景的车道数、车道宽度和参考线左右边界 | 规划及 GUI；车道初始默认值会被当前 run 上下文覆盖 |
| 规划/控制算法参数 | 权重、采样距离、求解预算、安全余量 | 模块独立配置；已创建对象不保证热更新，修改 YAML 后重启；控制算法切换按新 run 重建 |

没有车辆字段的旧上下文继续使用备用值：局部规划采用自己的备用尺寸，独立泊车库继续采用 `ParkingConfig` 默认值。正常 launch 会发送完整车辆字段，因此物理参数应只在仿真器配置。

## 不应强行统一的数值

- `plan_period`、控制定时器周期、物理周期、结果轮询周期和 GUI 帧率职责不同。控制的模型周期必须匹配物理周期；规划周期和显示刷新率无需相等。
- 仿真命令超时和安全规划超时使用墙钟；控制路径年龄、候选命令年龄使用仿真时钟。两者用于不同的失联检测，不能仅因默认数字不同而认为失配。
- DP、QP、输出路径、Routing 和参考线各有采样网格；其间通过弧长及几何插值衔接，不要求点数或间距相同。
- 碰撞余量和走廊余量是算法安全设置，不是车辆真实尺寸。泊车纵向输出是归一化控制器增益，不是巡航 PID 的物理加速度接口。
- LQR/MPC 的线性执行器模型没有显式包含仿真中的非线性转角速率饱和。它是已知模型近似；参数同步不能消除这一近似。泊车控制也未实现动态转向延迟补偿。
- 巡航 LQR/MPC 当前固定采用动态自行车模型，不会根据上下文的 `vehicle_model` 切换为运动学模型。figure-eight 为动力学场景；默认/障碍物场景为运动学，且动态车辆在低速也退化到运动学。两种模型现在共享车辆几何、限幅和时间参数，但预测方程仍有差异。本次未改写模型选型；若要追求两种仿真模型下的严格响应一致，需要单独实现运动学预测模型并做闭环对比。
- `max_lateral_deviation_m`、`boundary_margin_m` 在参考线当前流程为已声明但未执行二次平滑的预留参数，YAML 已标注；不能当作当前生效的平滑约束。
- 评估工具的质量/刚度扰动和控制器执行器参数扰动用于鲁棒性对比，允许有意与真实模型不同，不能在实验入口自动消除。

## 验证

`test_parameter_consistency.py` 检查非默认物理周期、重置、车辆限制、速度单位、jerk 限制，以及冲突/非法参数。`test_ros_lifecycle.py` 以两次不同 run 检查局部规划、巡航与泊车同步自定义车辆，再切回默认参数，避免只测默认值掩盖失配；同时验证拒绝物理周期热修改。实际 ROS 行驶回归覆盖理想/动态转向的 figure-eight，以及障碍物场景和规划交接。
